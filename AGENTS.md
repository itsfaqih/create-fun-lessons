# Agent notes

This repo ships the `create-fun-lessons` skill in `skills/create-fun-lessons/` for anyone to install.

- Keep the skill's wording portable: name generic tools and steps (`node`, "a browser", "the user's or project's output folder", "a URL the phone can reach"), not one person's setup, wrapper commands, or apps.
- Describe the learning experience itself (lesson map, quick cards, instant feedback, retries, overall progress) instead of naming other learning products.
- Every code sample, command, and code answer field is syntax highlighted (highlight.js, loaded in `template.html`). A new card type or field that shows code renders it through `highlight()` or the `field()` editor and takes a `lang`; the checker (`scripts/schema.mjs`) rejects languages the page does not load.
- Every quiz card offers a Hint button. A new quiz card type defines its automatic hints in `hintSteps()`, or its `needsHint` in `scripts/schema.mjs` requires an authored `hint`.
- Every quiz card shows its acceptance criteria before the learner answers: the question or options make it plain, a `type` card states its expected form and matching rule, a `blanks` card states its blank count and spare chips, a `write` card lists its rubric.
- On a miss, feedback marks each wrong part and shows the right answer: the option, the order, every blank, the accepted command, or the sample answer.
- Chip cards (`order`, `blanks`) take every input: tap, keyboard (Enter or Space on a chip acts on that chip; arrow keys move a placed `order` chip), and in `order` a drag with pointer events, from anywhere on the chip with a mouse and from its grip or after a long press on touch, while the other chips move aside.
- A course covers its whole subject, proven by `syllabus.md`: every part of the subject maps to lessons (through each lesson's `covers`) or a stated skip reason, and `lessons.mjs build` and `check.mjs` enforce it.
- Progress lives in the browser's `localStorage` under `storageKey`, so it belongs to one origin (scheme, host, port). The skill delivers every course at a home that keeps that origin across visits: the page file on a desktop, or a detached server on a fixed port and a stable address the phone can reach, recorded in `homeUrl` (`course.json`). A change to how the engine stores progress updates SKILL.md's Saved progress section, which lists what keeps and what loses progress, in the same commit.
- Courses are authored as a course folder (`course.json`, `syllabus.md`, `lessons/<unit id>.md` holding each unit's lessons under explicit `id:` lines) and built into one page by `scripts/lessons.mjs`; agents never hand-edit the built page. The card-type registry in `scripts/schema.mjs` drives both the checker and the lesson file parser, so a card type's fields are declared once.
- A change to the card schema touches `template.html` (engine and sample lesson), `scripts/schema.mjs`, the lesson format in `references/lessons.md`, and `SKILL.md` together. Verify with `node --test test/lessons.test.mjs` from the repo root; it also runs `check.mjs` on a copy of the template with its own `storageKey` and a `syllabus.md` that maps lessons `u1l1` and `u1l2`.
- Code boxes fit 41 columns at a 400px viewport and the write answer editor 36 (`CODE_COLUMNS` in `scripts/schema.mjs`, measured in a headless browser with the template's fonts). A change to code font size, padding, or the page gutter remeasures them.
- The page looks like shadcn/ui, built on Basecoat CSS (`basecoat-css` from jsDelivr, pinned) with Inter from its official CDN (`rsms.me/inter/inter.css`, `InterVariable` with static `Inter` as fallback) for text, Geist from Google Fonts for headings (course title, unit and card titles, the done screen; chosen over Manrope and Inter), and Geist Mono from Google Fonts for code. Reuse Basecoat's components (`.btn` with `data-variant`/`data-size`, `.badge`, `.progress`, `.kbd`) and its tokens (`--background`, `--card`, `--border`, `--muted-foreground`, `--primary`, `--destructive`, `--radius`) before writing new CSS; add a course-specific rule only for parts Basecoat lacks. Dark mode is Basecoat's `.dark` class on `<html>`, which the engine sets from the system theme. Basecoat already owns `.card`, so the lesson body is `.panel`. Progress is shown only as lessons done out of the whole course (the map's bar and the lesson-complete screen's Course tile); the page has no XP, streak, or other points. The lesson-complete screen has one button: "Next lesson", or "Back to map" after the last lesson.
- Learners can always step back. In a lesson, the Back button returns to the previous card, and an answer given there is practice that leaves the score and retry queue as they were; resume picks up at the furthest card reached. A lesson is one browser history entry above the map, so the browser's back button or gesture returns to the map. The map resets one lesson, one unit (the row's and the unit header's reset buttons), or the whole course, each after a confirm.
- Motion in the page runs at the speed of a real product: feedback starts on the input; colour changes take about 200ms; what appears opens its own room (`open` plus `drop`/`rise` keyframes) rather than popping in; changed labels roll (`relabel`/`roll`), and the button around them stays put; a moved chip glides from its old place to its new one (`glide()`); the progress bar travels between cards; landings are soft, with no bounce or ring pulse. Status text and filled buttons use `--ok-text`/`--bad-text` and `--ok-fill`/`--bad-fill` so they stay legible in both themes. Everything respects reduced motion.
- Visuals in cards are inline SVG on a 320-unit viewBox, coloured only by the template's `.viz` classes (theme tokens plus the unit colour), so each reads in both themes and fits a 360px phone; a CDN library joins only for a picture inline SVG cannot draw. The patterns live in `skills/create-fun-lessons/references/visuals.md`, and a new pattern lands there and in the sample lesson `u1l2` together.
- The landing page in `site/` uses the template's look: the same neutral tokens, Inter for text, Geist for headings, Geist Mono for code, near-black buttons, and status colours. Its miniatures (`site/src/styles/product.css`, and the card tiles in `site/src/components/CardTypes.astro`) mirror the template's parts, so a style change to `template.html` updates them in the same commit.
- The landing page keeps two pitch lines by the owner's choice: the hero's "Turn a codebase into a course you'll finish." and the progress heading "Small wins, and a reason to come back tomorrow." Plain-language passes leave them as they are.
